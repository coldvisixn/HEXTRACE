# GHOSTMAP — Lightweight Native Pentest Workstation

Ты — Senior Python Developer, Qt Desktop Engineer, UX Designer и Performance Engineer.

Разработай GHOSTMAP — самостоятельное графическое desktop-приложение для Kali Linux, объединяющее автоматизированную разведку, визуальную карту инфраструктуры, менеджер пентест-проектов и конструктор цепочек атак.

Вдохновение: BloodHound, Legion, Faraday, Obsidian и Linear.

## 1. Главная философия

Создай инструмент, которым будет приятно пользоваться каждый день при решении Hack The Box и проведении разрешённых проверок безопасности.

Три одинаково важных приоритета:

**Functionality:** приложение должно действительно помогать в пентесте, а не просто красиво выглядеть.

**UX/UI:** интерфейс должен быть современным, продуманным, быстрым и визуально качественным.

**Performance:** приложение должно комфортно работать внутри виртуальной машины Kali Linux с 4 GB RAM и небольшим виртуальным SSD.

Нельзя добиваться лёгкости ценой удаления важных функций или примитивного дизайна.

## 2. Обязательный стек

- Python 3.
- PySide6, используя Qt Widgets, Qt Core и Qt GUI.
- QGraphicsScene / QGraphicsView для графа.
- SQLite через стандартный модуль sqlite3.
- QProcess для запуска и управления внешними инструментами.
- Qt Style Sheets для оформления.
- SVG-иконки и минимальный набор ресурсов.
- Нативная упаковка в Linux `.deb`.

Не используй Electron, Tauri, Chromium, WebEngine, Flask, FastAPI, React, Docker или постоянно работающий локальный сервер.

Используй Qt Widgets вместо Qt Quick/QML в первой версии.

Не включай полные копии Nmap, Python и Qt в установочный пакет, если можно использовать системные зависимости Kali.

## 3. Интерфейс

Создай профессиональный тёмный интерфейс.

Основное окно:

**Левая панель:** проекты, хосты, граф, сканирования, цепочки атак, заметки и инструменты.

**Центральная область:** интерактивная карта сети или выбранный рабочий модуль.

**Правая панель:** свойства выбранного узла, находки, связанные объекты и действия.

**Нижняя панель:** активные сканирования, вывод инструментов, история задач.

Используй QSplitter и настраиваемые панели. Сохраняй их размер и расположение.

Нужны аккуратная типографика, качественные контекстные меню, горячие клавиши, поиск и понятная визуальная иерархия.

Избегай тяжёлых анимаций, чрезмерных эффектов и постоянной перерисовки интерфейса.

## 4. Главный модуль — Network Graph

Реализуй интерактивный граф наподобие BloodHound.

Возможности:

- Host → Service → Finding → Credential → Access.
- Масштабирование колёсиком мыши.
- Перемещение графа.
- Перетаскивание узлов.
- Автоматическое размещение.
- Создание пользовательских узлов и связей.
- Карточки с подробной информацией.
- Цветовая индикация статусов.
- Фильтрация и группировка объектов.
- Сохранение координат каждого узла.
- Возможность строить собственные цепочки атак.

Поддерживай различие между подтверждёнными находками и гипотезами.

Для рендеринга используй QGraphicsItem. Минимизируй ненужные перерисовки, оптимизируй отображение рёбер и группируй сервисы, если граф становится слишком большим.

Не выполняй тяжёлую автоматическую раскладку графа непрерывно.

## 5. Recon Engine

Пользователь создаёт проект, указывает разрешённый IP, домен или диапазон и запускает проверку.

Интеграции:

- Nmap: порты, версии, сервисы, подходящие NSE-проверки.
- WhatWeb: веб-технологии.
- httpx: HTTP-метаданные.
- ffuf: исследование путей в рамках заданной области.
- Возможность добавлять собственные инструменты через плагины-адаптеры.

Система должна уметь анализировать результаты и создавать узлы графа автоматически.

Профили: Quick, Full, Service Enumeration, Custom.

Не запускать эксплуатацию уязвимостей автоматически. Проверки с повышенным риском или нагрузкой требуют явного подтверждения.

Секреты хранить безопасно, не писать в логи и не использовать автоматически.

## 6. Оптимизация

Цели производительности:

- Желательно не более 200 MB RAM в простое.
- Желательно не более 300 MB RAM во время обычной работы без учёта внешних сканеров.
- Минимальный собственный размер приложения.
- Один ресурсоёмкий сканер одновременно по умолчанию.
- Никаких неиспользуемых постоянно работающих процессов.

Используй ограниченные буферы логов, ленивую загрузку данных, постраничный вывод больших результатов и эффективную обработку графа.

Не загружай всю базу проекта в память.

Сохраняй обработанные результаты в SQLite. Полный исходный вывод инструментов сохраняй по необходимости с настраиваемым сроком хранения.

Не блокируй главный Qt event loop при сканировании, парсинге или обработке больших данных.

Проводи реальные измерения RAM, CPU и диска. Если лимит превышен, выясняй причину и оптимизируй. Не выдавай целевые показатели за достигнутые без измерений.

## 7. Установка

Конечный результат — нативное desktop-приложение для Kali Linux.

Требования:

- Устанавливается через `.deb`.
- Появляется в меню приложений.
- Запускается отдельным окном.
- Не требует открывать браузер.
- Работает офлайн.
- Сохраняет проекты и настройки между запусками.
- Имеет нормальную процедуру удаления.

Используй системные зависимости Debian/Kali и проверь их фактический размер до сборки.

Избегай PyInstaller --onefile, если это заставляет дублировать крупные системные библиотеки.

## 8. Разработка MVP

Сначала реализуй только:

1. Рабочее главное окно со всеми базовыми панелями.
2. Создание и сохранение проекта.
3. Добавление IP-адреса.
4. Реальный запуск Nmap и отображение прогресса.
5. Разбор Nmap XML.
6. Автоматическое создание Host и Service nodes.
7. Интерактивный граф с zoom, pan и drag.
8. Ручное создание связей и заметок.
9. Сохранение и восстановление карты через SQLite.
10. Сборку и установку `.deb`.

Дальнейшие модули добавляй постепенно, не ломая работающий MVP.

Перед разработкой определи архитектуру, структуру каталогов и зависимости. Затем переходи непосредственно к реализации.

**Критерий готовности MVP:** я запускаю приложение в Kali с 4 GB RAM, ввожу IP HTB-машины, сканирую её, получаю красивую интерактивную карту реальных сервисов и продолжаю работу с ней после перезапуска программы.
