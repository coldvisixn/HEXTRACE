## Правила продолжения

- Сначала прочитать этот файл и проверить `git status`.
- Продолжать последний незавершённый этап, не повторяя выполненную работу без изменения входных данных.
- Работать автономно в рамках задания, завершённые этапы фиксировать локальными Git-коммитами.
- Перед остановкой обновлять состояние, результаты и подробные следующие шаги. Показатель остатка дневного лимита агенту недоступен: точное достижение порога 5% определить невозможно.
- Использовать существующий `/workspace/HEXTRACE`: облачная задача уже изолирована. Не создавать worktree без запроса.
- Не сохранять секреты в код, SQLite, логи или коммиты. Credential nodes — ссылки на внешний менеджер секретов.
- Не отправлять коммиты на сервер без соответствующей задачи; не сбрасывать локальную работу к удалённой ветке.

## Задание и архитектура

Пользователь предоставил спецификацию GHOSTMAP; копия: `docs/SPECIFICATION.md`.
Первая цель — работающий нативный MVP для Kali: проекты, IP, Nmap, XML, карта,
ручные связи/заметки, восстановление через SQLite и deb.
Архитектура и структура: `ARCHITECTURE.md`. Инструкции запуска: `README.md`.
Стек: Python, PySide6 Widgets/Core/Gui, QGraphicsScene/View, SQLite, QProcess,
QThread для XML, QSS, SVG. Серверов и браузерных зависимостей нет.

реальной Kali VM ещё не подтверждён: машина здесь Debian и нет прав root для

тесты сканируют только локальный fixture. Не объявлять полный сценарий Kali проверенным.

Бинарные outputs (`dist/`, `build/`), зависимости и базы игнорируются Git.
Приложение не запущено постоянно. Секреты и дополнительные network rules не требуются.
Коммиты существуют только локально, удалённая main остаётся неподтверждённой.
Нельзя утверждать, что свежая задача восстановлена или локальные коммиты опубликованы.

## Последний незавершённый этап: проверка Kali VM

1. На Kali VM с 4 GB RAM проверить размеры зависимостей `apt-cache show` и
   `sudo apt install --simulate ./dist/ghostmap_0.1.0_all.deb`.
2. Собрать `python3 scripts/build_deb.py`, установить
   `sudo apt install ./dist/ghostmap_0.1.0_all.deb`.
3. Запустить через меню и CLI `ghostmap`. Проверить отсутствие browser/server процессов.
4. Создать проект, добавить разрешённый HTB IP, запустить Quick после подтверждения,
   дождаться результатов и сравнить сервисы с Nmap XML.
5. Переместить узлы, добавить Note и связь, сохранить, перезапустить и проверить карту,
   заметки, выбранный проект и размеры панелей.
6. Измерить RSS/CPU в простое и во время обычной работы; внешние сканеры считать отдельно.
7. Проверить `sudo apt remove ghostmap`: launcher/menu удалены, пользовательские данные
   сохранены. Обновить VALIDATION.md и этот файл фактическими результатами.

Если целевая Kali недоступна, не выдавать этот этап за выполненный. Независимое
развитие после MVP: группировка больших графов, domain/range scope, adapters для
WhatWeb/httpx/ffuf, NSE-профили, полноценные chains и secure secret storage.
Добавлять постепенно с проверками, сохраняя working MVP; не запускать эксплуатацию
автоматически и не использовать секреты без явного действия пользователя.
